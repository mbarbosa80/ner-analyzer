Concepts and acronyms

These terms appear on nearly every screen. Understanding the difference between a room and an occurrence, and between extracted and confirmed, is what separates using the tool from trusting it.

Term Meaning
NER Network Equipment Room. The room that serves an area's network points. It is critical or non-critical — and in this application that classification only counts once a person confirms it. Only a NER serves a space.
TER Telecommunications Equipment Room. Read off the drawing and drawn, it can be placed and moved, but it never serves a space and gets no reach circle — the TER↔NER relationship is a design rule this tool does not invent.
IDF / MDF · COW · DIVA node Other markers the drawing carries or you place: intermediate/main distribution frame, a temporary cabin (cell on wheels) and the DIVA rack. Visual only: they appear on the plan and on the exported PDF, and never serve any space.
TEAP The workbook stating technology equipment and service demand per location. It is the source of the question “how many network ports does this space need?”
VDB The venue's drawing set (PDF), used to identify spaces, functional areas, TERs and existing NERs. It is the source of the question “where is this space?”
TVDB The later document carrying containment, pathways, routes, shafts and risers. Not read by this version — see what the app does not do.
Space A named room or area. It exists in two places: on the drawing (a drawing space, with a page and a position) and in the TEAP (a TEAP space, with a port demand). The TEAP × drawing step is what ties one to the other.
As-Is The name of the saved coverage analysis: the drawing as it is, with whatever you have placed on it. The Demand per space screen and the reports read who serves what from it.

Room and occurrence

A design book draws the same room several times: once on the level key plan, again on a zone detail, again on a services overlay. The application keeps the two apart:

  • Canonical NER — the physical room. It has a name, a classification, a capacity, a position, a lock and a confirmation. Its internal identifier and its code never change, not even when you rename it.
  • Occurrence (marker) — where that room appears in a document: file, page, coordinate, the text the extractor read and the detection confidence.

A room drawn on four sheets is one row on the NERs screen with four markers — not four NERs. Without that separation the room count is inflated, and every number downstream inherits the error.

Four kinds of data, never mixed

KindMeans
extractedwhat a document said — the label read off the sheet, the printed scale, the TEAP line.
confirmedwhat a person signed off — a page's scale, a TEAP × drawing match, a NER's criticality.
estimatedwhat the tool inferred to keep going — a service point at the centre of a space, a port count assumed from the category.
decided by youwhat you chose by hand — the room serving a space, the drawing room that corresponds to a TEAP line. It outranks the automatic answer, lands in the audit log, and is still checked against distance and capacity.

Every row, every match and every result carries which of these it is. The exports say so row by row (Needs validation); the screens say so with pills, rings and notes.

The workflow

The left-hand navigation is the workflow, in order. Every step is disabled until a project is open.

The navigation folds: « at its top right shrinks it to a narrow rail of step numbers (1 to 8, with the name of each step when the pointer rests on it; ▤ is Projects and ⚙ Account & security), and » at the top of the rail opens it again. The drawing takes the width it leaves — useful on a laptop screen. The browser remembers the choice.

The application opens in the browser at http://127.0.0.1:8000, or from the NER Analyzer shortcut setup.bat puts on the desktop. It works in Google Chrome, Microsoft Edge and Mozilla Firefox, in a current version; Safari and Internet Explorer are not supported. On a corporate machine where Microsoft Edge opens http://127.0.0.1:8000 in Internet Explorer mode (the page stays blank or looks broken), use http://localhost:8000 — the same application, an address the IE-mode list does not catch.

Notices

What an action did is said in a notice that appears at the top of the window, over the page, green when it worked and red when it did not. It does not push the screen down — in the Drawing viewer the sheet stays exactly where it was under the pointer — and it goes by itself after a few seconds; a click closes it sooner.

The progress bar

Long operations — importing a 75-page PDF, matching thousands of rows, running the analysis, writing the marked-up PDF — run in the background and appear in a bar reading Working / Finished / Failed / Cancelled, with the current stage in words (reading page 12 of 34), the percentage, and the buttons Cancel (while running) and Dismiss (afterwards). The rest of the application stays usable meanwhile. When an operation fails, the message stays in the bar instead of vanishing.

If a screen fails

A screen that fails to draw shows the failure inside itself, with the message, a button to try again and one to reload — and the rest of the application stays up. Moving to another tab clears it.

A copy, not a link

Importing creates a new project with new numbers; nothing existing is changed, and the original stays where it was. From then on the two copies are independent: there is no merge and no synchronisation. Agree who carries on — whoever handed the project over should stop working on their copy, or the two will drift apart with no way of putting them back together. A package can be imported only by the same version of the app or a newer one; a package from a newer version is refused with the advice to update.

The package holds the venue's documents

It carries every design book of the project in full. It is not encrypted. Move it only through the channels your organisation approves for those documents — never a personal e-mail or a public link — and delete it once the other side has imported it. The application keeps only the newest package of each project in its exports folder. Every package is checked before anything is written: only the files its manifest lists are read, each against the SHA-256 recorded on export, so a package damaged or altered in transit is refused whole — … does not match the copy that was exported (damaged or altered in transit). Nothing was imported.

Why sharing does not grant editing

The application has no concurrency control. Two people confirming different matches on the same project would silently overwrite each other. Until that is solved properly, writing stays with the project's owner (and the administrators). The recipient of a shared project can open it and move through every screen; any change — building a report included — is refused with this project is shared with you for reading….

Step 1

Import

Three numbered cards: the drawings, the workbook, and the project rules.

1 · Drawings (PDF)

Choose one book or several at once — Ctrl or Shift in the file dialog. The import starts at once, in the background, with the progress bar naming the page it is on; several books are read one after the other, each to its end, and a list under the bar says of each one waiting, reading, imported (with its pages and spaces) or refused (with the reason). A book refused does not stop the others. The book is read by a second Python process started for the job (Task Manager shows it beside the server while the import runs); it ends with the import and gives its memory back, which the server itself would not. When it finishes it reports how many pages and spaces were read, how many NER annotations and NER rooms the book states (placed later, on the Scale screen) — and, if any, how many pages need OCR. From every page the importer reads the title block (drawing number, sheet title and level, when the title states one), the printed scales, the space labels and the room markers. On a sheet whose title block was read, the level is the one its DRAWING TITLE states (… - LEVEL 01) or none — a bare three-digit figure printed large on the sheet (a stand's seat count) is never taken for a level.

The table lists: File, Pages, Spaces, Markers, OCR needed (the scanned pages' numbers, or none) and, on each row, Remove.

The same book once

A book is refused, and nothing of it kept, when the same file is already in the project — whatever it is called: '…' is already in this project (the same file, imported as '…'). Nothing was imported. — and when a book with the same name but other content is: that is almost always a new revision, and two revisions side by side draw every room twice: a book named '…' is already in this project, with other content — a new revision? Remove the old one on the Import screen first, then import this one. The same file picked twice in one selection is dropped before anything is sent. A project that already holds the same file twice shows same file as … — remove one of them under the second copy.

Remove — taking a book out

Remove first counts what goes with the book and asks: its pages, rooms and markers; the NERs drawn only on it, by name; how many NERs are also drawn on another book; how many TEAP lines you tied to one of its rooms; and whether it is the same file as another book. Confirmed:

  • its pages, its rooms and everything drawn on it — markers, Wi-Fi points, illustrative areas, references, cable routes and shafts — go, and so does the stored PDF;
  • a NER also drawn on another book stays, placed where that other book draws it;
  • a NER drawn only on this book leaves the list, removed with the reason its book … was removed from the project (it shows among the removed NERs; Restore brings back the row, with no position, since its sheet is gone);
  • a TEAP line you tied to one of its rooms is untied, and the answer says how many — tie them again on the books that remain;
  • the matching runs again on the books that remain, so the TEAP lines find their rooms there.

It cannot be undone; run Run analysis afterwards. Remove waits while a background task of the project is running (a task is still running on this project…).

Several series of one book in one project

A venue design book comes in series — 300 (floor plans, a whole level per sheet), 400 (enlarged plans), 600 (seating bowls), 700 (field of play) — each a PDF of its own whose pages start at 1. Upload the series you want into the same project, one after the other: a space that only one series shows (at VAA the press tribune and the commentary positions are on the 600 series and nowhere on the 400) can then be crossed with the TEAP. Each sheet is known by its book and its page, never by the page number alone: the viewer, the lists, the exports and the analysis never take page 2 of one book for page 2 of another. The screens name a sheet by its series and page — 400 page 6 · VAA-411B3-VBV-O; the workbook by its drawing number — VAA-411B3-VBV-O (400 p.6).

  • One NER, one row, whatever the series. A room printed with the same numbered code on two series (TEC.010-007 on the 400 and on the 600) is one NER with a marker on each sheet. Placed by hand on another series, it is the same question as on another page: is it the same NER?
  • One space, one row. The TEAP line counts once. The same space code on another sheet, on the same level read off both title blocks, is linked to it as the same space; with a level unread on either sheet it is a question for you; on another level, nothing.
  • Distances are measured within one sheet — the space and the NER both on it, at that sheet's scale. A space on a 600 sheet with no NER drawn there is pending until the NER is drawn on that sheet too (or chosen under Served by).
  • The marked-up PDF is one file with every book, in the order they were uploaded.
One drawing version per project

A file that cannot be read as a PDF — damaged, password-protected, or not a PDF under a .pdf name — is refused with '…' could not be read as a PDF — the file is damaged, protected or not a PDF. Nothing was imported., and nothing of it is kept. A copy cut short in transit, which opens with no page at all, is refused the same way (… it opens with no page (damaged, truncated or not a drawing)).

Uploaded the wrong book? Remove takes it out (above). Do not upload a revised VDB into a project that already has the same series. A file with the same name is refused; a revision under a new name is not caught, and the application takes every book of a project as part of the same drawing set, so the old and the new 400 series side by side are two sets of the same rooms — the analysis would measure from a marker on one version to a space on the other. It does not error. The numbers stay plausible and are wrong.

When the VNI team returns the revised VDB, either Remove the old series and import the new one in the same project — the NERs drawn only on the old book leave the list, and the rooms are matched again — or create a new project for it and carry the previous analysis workbook's NERs and ports sheet (Reports) across for reference. One project per venue is right; one project per version of the same venue is the rule for as long as the application does not version drawings.

A ten-second check

After uploading the VDB, open the Drawing viewer on a page with named rooms. The grey space dots should land on the rooms in the drawing, and every NER marker on the label the drawing prints. If they are displaced in a systematic way, the problem is the document (an unusual page rotation), not the data — worth raising before moving on to scale and matching.

How a space is recognised

The importer first looks for the space code printed beside the room — the accommodation-matrix (AAM) naming: a functional area and a number, ACR.001, PRS.006.02, BRS.052.02-001 — and builds the space from it: code, name on the neighbouring lines, area. That is the case of the books that follow the TEAP taxonomy. On a sheet that prints no code at all — every room labelled by name alone, over two or three stacked lines — a name label becomes a space only when it reads as a known space name: one of the names of an Accommodation Area Matrix (AAM) list, when the copy carries one in its private reference folder (backend\app\reference_private\aam_names.txt: Venue Accreditation Office (VAO), Broadcast Mixed Zone, Athlete Medical Station …), or one of the names the project's TEAP prints, if it was imported first. Without that list, the project's TEAP names alone make the vocabulary. Similar means 80 % or better after normalisation, or a whole known name (of twelve characters or more) inside the label; a cable-length tag in front of the room (L9m (31ft) Venue Media Centre (VMC)) is stripped. Everything else a containment sheet prints — CABLE GOES UNDER BRIDGE, L145m (476ft), STRM SEWR, the pathway legend, the drawing index, the survey abbreviations — is not a space. Left out by explicit rule, as before, are the title-block column (legend, client-group key, general notes, revision table), the status stamps, the scale bar, the sheet references and the NER markers themselves. A space read this way comes in with no code, with evidence naming the known name it resembles; in the matching step it can only match by name, so it always lands on the review queue. A sheet with codes is unchanged. On a sheet ticked as a key plan (below) no space is read at all.

If the import table shows Spaces at zero on a book with named rooms, the drawing carries no room labels as text (a scanned plan, for instance), and the matching step will refuse to run and say so.

Key plans only illustrate

The overview sheets of a book — KEY ENLARGED PLAN - LEVEL 01, KEY FLOOR PLAN — repeat, at a small scale, the rooms of the detail sheets. The importer recognises them by the DRAWING TITLE in the title block (lower right): any title with KEY … PLAN is a key plan — and so are the other sheets that only illustrate: the DRAWING INDEX, the VENUE INFORMATION & GAMES MAP, the ABBREVIATIONS, the TYPICAL … SOLUTIONS, the symbols sheet, a cover or title sheet, general notes and legends. On a key plan: no space is read — nothing drawn, nothing in the search, nothing in the TEAP × drawing list — and it takes part in no crossing; no NER is placed on it; a NER written on it (a reviewer's red comment) comes in as a reference (*NER★ / *NER), drawn with its circles and counted nowhere. The page stays in the viewer for references and illustrative areas. The ticks are reviewed on the Scale screen — one box per page, Apply key-plan ticks — and the Key plan box in the Drawing viewer does the same for one page.

NERs the drawing already states

In the accommodation-matrix taxonomy (the AAM workbooks) TEC.010 is a Network Equipment Rack - Critical and TEC.020 a Non-Critical one; the older books filed them as TEC.003.01 / TEC.003.02, and both spellings are read (TEC.003-001, the Mobile Equipment Room, is not a NER). The import reads what the book says about its NERs — the team's own annotations (Critical NER 8 written on a sheet), those rooms, the Network Equipment Rack labels and the NER block symbols — and places none of them. That is a step of its own, Place NERs from the drawing on the Scale screen, to run once the key plans are ticked and the scales confirmed (the 12 m rule below needs the scale: on a page with none it is applied as 170 pt, which is 12 m only at 1:200). It creates the NERs nobody has drawn yet — for you to check and validate, instead of drawing them all from scratch — in this order: the team's annotations, then the coded rooms, then the labels, then the symbols:

  • What is read: the code in any of its spellings (TEC.010-003, TEC.020-003, a bare TEC.010; TEC.003.01-05, TEC.003.01.005, TEC.003.02 on older books) or, with no code, the label Network Equipment Rack (NER) - Critical / Non-Critical or, as the newer books print it, Network Equipment / Rack - Non-Critical (two lines, no bracket — a lone Rack - Critical with no Network Equipment over it is not a room). A sentence in a note or the legend is not a room.
  • The NER block symbol: the newer books draw most racks not as rooms but as a small orange square with the word NER inside, in a dashed rectangle in the area it serves. The word is not text on those sheets (the CAD plots it as strokes), so the application recognises the block by its shape, against a reference block, whatever its size or angle; the colour decides nothing. A symbol is a NER at the square's centre, non-critical with its criticality pending (the symbol does not say); a symbol drawn inside a room already read is that room's rack, not a second one; a symbol at the same position as a symbol on another sheet (a ground-floor rack repeated on the floor above) is created and asks whether it is the same rack. Its evidence names the shape distance and the stroke count.
  • Where the NER goes: when the label has an arrow to the room, the leader is followed to the arrow's tip and the NER goes there; on a label stacked with another room's name (… Critical / Commentator Control Room (CCR)) the arrow leaving the NER's lines counts. With no arrow, the NER sits on the label.
  • Criticality: the code decides (-Placeholder with .01 is critical); with no code, the label's words. If the drawing does not say, the NER comes in non-critical with its criticality pending — the criticality not stated tile on the NERs screen filters those rows, and the row can only be confirmed once you choose.
  • Where there is already a NER: a NER written on the drawing or drawn by you within 12 m of the room, on the same sheet, is that room — no second NER; the code is recorded on it, and if its criticality disagrees with the drawing's the row asks which is right. One existing NER may answer for several rooms near it (racks labelled side by side in one cabin, one NER drawn for them): no new NER is created near one that exists.
  • The same code on two sheets (two overlapping detail sheets) is one NER, with a marker on each sheet — when the code carries a room number (TEC.020-003). A bare class (TEC.010) printed on two sheets is two racks.
  • Name: in sequence, by the application's own rule — NERc_01.1, NERc_02.1 … for a critical room, NER_20.1, NER_21.1 … for a non-critical one (the critical series starts at 01.1, the non-critical at 20.1; the .1 is the rack — a second rack beside it is .2, renamed by hand) — in reading order within each group — the annotations, then the coded rooms, then the labels, then the symbols — by page, then top to bottom; what the sheet printed (TEC.003.01-05, Critical NER 8) is kept as printed as. Rename them on the NERs screen as you like.
  • Running it again adds only what is still missing: every candidate finds the NER already there — a NER you removed included: its markers still hold the spot, and the room is not created again. A duplicate that slips through is yours to delete in the Drawing viewer (Delete only this marker when the room is drawn on other pages too). A NER whose drawing you take off a sheet - with Delete only this marker or by a move on the composite map - is not drawn back on that sheet, wherever the sheet prints its code; where the application knows only the sheet and not the spot, the whole sheet is kept off for that NER.

Every NER created this way comes in not confirmed, with the origin from the drawing (an annotation) or from the room label (a room or a symbol) and, in its evidence, the label as printed — NER for a symbol — and how its position was found. The notice at the end of the import says how many annotations and rooms were read; the notice at the end of the placing step, how many NERs were placed.

A CSV has no sheet and no venue filter: the header is always the first line and the whole file is imported, every venue in it — for a programme-wide TEAP, use the XLSX.

The application's most expensive mistake

Ticking import every venue on a programme-wide TEAP pulls dozens of venues into a project that holds the drawing of one. Because the space-code taxonomy is shared across venues — SPT.016.01 exists in dozens of places — the matching pairs other venues' rooms against your plan with high confidence, and nothing in the matcher checks the venue. Measured on a real project, of 2,873 matched rows only 74 (2.6%) belonged to the right venue; every coverage figure after that is noise that looks like a result. Always pick the venue.

Colour does not classify

The naming reference

Possible duplicates

When the same name appears on different pages — NER 5 on 7 and on 8 — the app does not merge on its own: it scores the pair below the automatic threshold and brings it to this panel with the evidence that they are the same room (“identical normalised label”, “same marker kind”, “appears on pages 7 and 8”) and the differences found (“level not stated on at least one page”), side by side. The pill gives the score and whether the evidence is strong (strong evidence) or calls for judgement (needs judgement); below it the impact: how many markers change row and how many served areas are reassigned.

  • Same NER — consolidate: the two become one NER with two markers, one per page, and the whole coverage analysis counts one room instead of two. Write the Justification (what makes you sure) first. Reversible with Undo under Consolidation history.
  • Different NERs: the pair stops asking.
  • Or leave it for later — nothing changes.

Step 5

TEAP × drawing

Match each TEAP row to a drawing space. Nothing low-confidence is confirmed silently.

Key plans are left out

A room on a key plan (see Import) is not offered to the automatic matching, does not appear in the Drawing space list and is refused if sent by hand (this room is on a key plan…). A key plan repeats the rooms of the detail sheets, and tying the TEAP there led to the right room on the wrong page. A tie to a room that comes to be on a key plan is released — even one you confirmed —, recorded in the audit (matching.key_plan_released, with the room and the page) and the matching looks for the room on a detail sheet; if it finds none, the line goes to no room found. The same space on other pages column ignores the key plans too.

The TEAP rules

The TEAP says whether an area is served. The check runs from the TEAP to the drawing, never the other way round: a room that is on the drawing and that no TEAP line asks for is not listed, not counted and not a finding — however likely it looks that it will need service one day. And a TEAP space whose lines add up to zero network ports asks for nothing a NER can give: it is matched silently and left off this queue, its tiles, Demand per space, Exceptions, the analysis and the workbook's main sheet. It is a filter, not a deletion — the scope is worked out from the imported lines, so a later TEAP that gives the space a port brings it back by itself.

One exception. A space with zero ports whose lines request wired connections (Wired Connection …, RJ45) with a quantity above zero stays on every list, at zero ports, with the reason written on the row. The TEAP counts the port on the device, not on the service; where users bring their own equipment there is no device line and the port is never counted — the photographer positions on the FOP and the press tribune are the cases. The application invents no port for those lines: it shows the space, measures the distance and leaves the count to be validated with the TEAP owner.

A book with no space code

On a book that labels rooms by name alone (see How a space is recognised), the code steps do not exist: everything matches by exact name, normalised name or similarity. An identical name on a TEAP line with no code, answered by one room only, is confirmed by the matcher like an exact code; everything else reaches this queue for confirmation. Expect three things. (1) Several TEAP rows with one name (SEC.005-01 to -07, all Pedestrian Screening - Accredited (PSA)) point at the same drawing label — pick the right room for each. (2) One name printed twice on the sheet (two concessions, two Announce Position) is legitimate ambiguity, not an error. (3) The rooms with the largest demand may not be labelled at all: a VDB that draws a pavilion as one block (North Pavilion: Three Levels) shows neither the press tribune nor the photo work room inside it. For those, the worklist lets you pick any room on the drawing, or the row stays unmatched until the book details the interior. Normalisation already treats Centre and Center as one word.

The order of attempts

exact code → base code → exact name → normalised name (abbreviations and synonyms folded in) → text similarity

The code comes first because the drawings carry the same code taxonomy the TEAP uses — matching on the code is exact, explainable and language-independent. The name is the fallback: synonyms and abbreviations act inside the normalised name and the similarity, not as a step of their own, and the building named on the TEAP line only nudges the confidence when it appears in the room's name. A base-code match (PRS.006.02 against PRS.006) is never confirmed on its own: it may be the same room or the one next door, and it is precisely the row that needs a person.

What the matcher confirms itself — the exact matches. Two answers need no person: an exact code with no rival room, and an identical name on a TEAP line that carries no space code, when only one room on the drawing answers to it. Those rows arrive confirmed, with a green ✓ exact where the Confirm button would be. An identical name on a TEAP line that does carry a code the drawing does not print is not confirmed — the name alone may belong to the room next door — and neither is a name or code that two rooms answer to. A project matched before this rule confirms its identical names at the next Run matching; your own decisions are kept as always.

How to judge the queue

A smaller queue is not automatically a better one. What matters is what each remaining row asks you. Demand per space

How many network ports each space demands, which NER serves each one, at what distance, with what status — and the button that produces that answer, on the same screen.

The serving-room rule

  1. The TEAP names the room. When the imported sheet carries a serving-NER column (mapped on Import as serving ner) and the name matches a NER on the list, there is no doubt: the row shows TEAP: … and named in the TEAP — no doubt. It is resolved by name (NER 03 finds NER 3; an earlier name still finds a renamed room). If no NER carries that name, the row warns in amber and moves on to the next rule.
  2. You chose. The Served by select on the row, with a justification recorded in the audit log. It outranks the TEAP when both exist — you are looking at the drawing and the TEAP is not — and the row says which one applied.
  3. The nearest NER within the limit that still has free ports. If the nearest is full, the next one. If every room within reach is full, the nearest anyway — with status Insufficient capacity, the ports counted in that NER's load (utilisation goes past 100%) and the row under Exceptions. The overload is reported, not hidden: the decision to draw a second NER there is made on the report.
  4. No NER within 90 / 70 m. Nothing serves it. The row says — none within 90 m · nearest: NER 5 at 120 m, status Out of limit, and the ports go on nobody's load — the cable does not reach.

Whichever leg chose the room, distance, limit and capacity are still evaluated and reported: a chosen room 200 m away comes back Out of limit; one with no ports free comes back Insufficient capacity; and both land under Exceptions like any other. Letting the choice silence those checks would turn the list into a way of laundering a violation — and would destroy the use case: you choose because the other room is overloaded, so the tool has to keep saying so.

A room the matcher found is served before you confirm it. When the TEAP × drawing match of a space is not confirmed yet — the matcher placed it on a room and nobody pressed Confirm, or the same code is on two sheets — the space is still measured from that room and served by the nearest NER under the usual rule: the status is the distance's (Served, near the limit, Out of limit), its ports count on that NER, and it does not go to Exceptions. What stays is the warning: the Matched to column says room not confirmed, the counter served — room not confirmed above the table lists those rows (click it to filter), the PDF keeps the orange rectangle around the space and the workbook says yes under Needs validation. If the room is wrong, the NER is wrong too — confirm or correct the room on TEAP × drawing, then Run analysis.

A space whose page scale is not confirmed yet gets the status scale not confirmed. With no NER fixed, it is not assigned — that result stays blocked on purpose — and the row shows the nearest room and its distance beside it, rather than a dash. With the NER fixed (chosen by you under Served by or named by the TEAP), the space is assigned to it and its ports count on that NER's load, but the status stays scale not confirmed until the scale is confirmed. A page with no scale at all measures nothing: there the space comes back No NER reaches it, not scale not confirmed.

A NER on another page

A space on level 2 may be served by the NER directly below it on level 1, through a shaft — or by the NER on the neighbouring sheet of the same level. The automatic rule never assumes that — the app does not cross pages on its own — but your choice holds: choosing in Served by a NER that sits on another page is itself the statement that it serves the space (you are looking at the design, the levels and the shaft; the app is not). On the next run that NER serves the space, the ports count against its capacity, and the status is Other level — not measured, in the Served — not measured group: no distance is invented, because two sheets share no coordinates. A TEAP space the drawing does not show

The TEAP's wireless and the Wi-Fi points drawn

What goes on a map

Two series are never mixed: a project with the 400 and the 600 books has maps of the 400 book and maps of the 600 book.
  • Never the key plan. Key plans (ticked on the Scale screen) are not drawn: the map is laid out against them, as the reference, and is made of detail sheets only.

How the sheets are placed

Every sheet is placed by two independent measurements, and the two check each other:

  • Match lines. The heavy dashed lines a sheet prints where it continues, read against the grid the key plan draws with the same lines and the sheet's zone (A1 in 412A1). Exact when the book follows that pattern.
  • Correlation with the key plan. The linework of the sheet compared with the key plan around the label the key plan prints for it (412A1-XXX-OP, or the zone letter). Works on any book whose key plan shows the linework.

When the two disagree by more than 2 m the correlation is kept — the match lines assume a regular grid, and the books that break it are the ones where they disagree. Then every pair of sheets that overlap is compared directly, within 4 m of where they were put: a pair that lines up confirms both sheets and corrects a few metres at most; a sheet is never moved farther than that by its neighbours.

The distance rules

  • A network point, device or access point sits at most 90 m from its serving NER.
  • A photographer point or area sits at most 70 m.
  • Both limits, the near-limit ratio (Near-limit threshold) and the slack factor are configurable per project in step 1.
  • Where a cable route is traced, the distance is the route length. Where it is not, it is the straight line multiplied by the slack factor, and the result carries the warning Preliminary straight-line distance. The result must be validated against the real cable route.
  • Cross-floor service is not assumed: it is only measured when a shaft, riser or vertical route is registered. The exception is your choice (or the TEAP's): a NER you chose on another page serves and counts against its capacity, with the distance reported as not measured until the vertical route exists — see Demand per space.
  • A TER, an IDF, a COW or a DIVA node never serves. Where a room polygon exists, compliance is evaluated against its farthest vertex, not only its centre; where there is only a point, the point is the space's estimated centre and the analysis says so in the assumptions.
Read before trusting a green result

A straight line is not cable length. Every straight-line result in this application is a screening number. The 90 m in ANSI/TIA-568 and ISO/IEC 11801 is the permanent link: installed cable along its real route, inside a 100 m channel that reserves 10 m for patch cords. Cable rises into a shaft, runs in tray around structure and drops back down, so a straight-line measurement systematically under-reports the installed length.

Raise the Routing slack factor to 1.25–1.40 for an arena bowl, or trace the real containment, before treating a green result as a design decision. At 1.0 the app is reporting raw geometry, and says so in the notes column.

Every calculation is deterministic: the same input always produces the same result, and no language model takes part in any of it.

Treat the port total of those rooms as a floor, not a final figure. Wi-Fi is different: the TEAP requests a space's wireless as a line with one port (the access point's uplink), and that port always counts on the space — the access points drawn on the sheet are positions, never ports (see Demand per space).
A room with no text label does not exist for the app A space is only read from a code or a name label in text on the sheet. A room drawn with no label, a label that is part of the image (a scanned plan) or a pavilion interior drawn as one block never becomes a space — the TEAP row stays unmatched and it is for you to pick the room on the worklist, or to accept that the book does not show it. The app creates no room where it reads nothing.
A NER read off the drawing is a reading, not a design The placing step creates a NER where the drawing prints TEC.010 / TEC.020 (or TEC.003.01 / .02), the Network Equipment Rack label or the NER block symbol, and it takes part in the analysis until it is deleted. On a book the team has already commented (the red NERs), the architect's rooms more than 12 m from every red NER become new NERs — perhaps rooms the team decided not to use. Check the from the room label rows before carrying numbers forward. The arrow is only followed when it is a thin line to a solid arrowhead; any other shape (a curve, no head) leaves the NER on the label, with the warning. A label with no code on two sheets becomes two NERs — consolidate them on the NERs screen. The block symbol is recognised against one reference block (one design team's); a venue drawn with a different block — another word, another lettering — is not read until its block is added to the reference. A room drawn with no text and no symbol is not read.
TVDB is not read Containment, pathway, Route A/B, shafts and redundancy are not analysed. Every distance with no traced route is a straight-line screening number, and every NER carries “no TVDB route validated” as a pending validation.
A traced route and a measure are flat The route and measure tools measure on the plan, on the sheet's one scale: they do not add the rise from the room to the tray, the drop to the outlet or the rack, or the service loops — all part of the 90 m permanent link. A route of 85 m with two 4 m drops is already over. And a page has one scale: a line drawn over an enlarged detail printed at another scale on the same sheet is measured at the wrong one. Read both as the horizontal part of the cable, not the installed length.
No venue guard in the matcher A space from another venue can match your drawing. The only defence is the venue filter in step 1. Always check that matched spaces belong to the project's venue.
No drawing versioning A second VDB version of the same drawings in one project is read as more sheets of the same venue: the pages do not collide, but the old and the new rooms are measured side by side as though both were built. There is no reconciliation screen — the app cannot answer “did they draw what I asked?”. Use a new project per version.
A project package is a copy, not a link Importing a package creates an independent project. Changes made on either copy never reach the other, and there is no merge: agree who carries on before anyone works on the copy. A package written by a newer version of the app cannot be imported by an older one, and it is not encrypted — it holds every design book of the project.
No OCR Scanned pages are flagged, not processed. They show OCR needed and nothing is extracted from them.
Spaces are points The room polygon is not extracted from the drawing; the space is estimated as a point. Large rooms carry more error.
Level comes only from the title block A sheet's level is read from the title block's DRAWING TITLE (KEY ENLARGED PLAN - LEVEL 01 → LEVEL 01). A sheet whose title does not state the level has none, and the duplicate queue asks instead of merging. The level the drawing number implies (-440B5- → level 04) is used only for the “same space on another page?” question, as weaker evidence: good for ruling another floor out and for making your answer easy, never for linking by itself.
One machine, one writer at a time It runs locally and listens on 127.0.0.1 only. Several accounts, but no concurrency control: sharing grants reading, and only the owner (or an administrator) writes.
No two-point calibration There is no tool to click two points on the sheet and type the distance between them. A page's scale comes from the printed scale, the title block or the ratio you type on the Scale screen; a sheet with no printed scale and no known ratio cannot be measured.
Jobs do not survive a restart An import, a matching run, an analysis or a PDF export that is running when the server stops is lost, not resumed. Run it again once the server is back; nothing half-written is kept.
No scenario restore Every analysis replaces the project's one As-Is scenario. An earlier result survives only as the workbook you exported from it.
No automatic NER proposal There is one proposal, and it is the drawing: the placing step reads the team's annotations and the rooms and symbols the design team already drew (TEC.010 / TEC.020, TEC.003.01/02, the Network Equipment Rack label, the NER block), but it invents no position — new NERs are placed by hand in the Drawing viewer. The tool's job is to say what each placement costs — the distances, what falls outside the limits, what nothing reaches. Power, cooling, physical space, security and A/B independence are not in the model, and that is why the decision is yours.

Running and maintenance

How it starts

After setup.bat, by itself: a Windows scheduled task starts the server at every sign-in, with no window, and the NER Analyzer desktop shortcut opens it in the browser. By hand, two ways. start.bat opens a console window that is the server — closing the window stops the application — and opens the browser at http://127.0.0.1:8000 as soon as it answers. Or, after running autostart.bat once, a Windows scheduled task named NER Spatial Coverage Analyzer starts the server at sign-in, with no window, and stop.bat stops it.

task .python\pythonw.exe tools\serve.py · trigger: at sign-in log data\server.log manual start.bat · stop.bat · tools\server-start.cmd · tools\server-stop.cmd
Cold start: 20 to 40 seconds

Loading the libraries and running the database migration takes that long. Allow that margin before concluding it failed. The line Application startup complete in data\server.log marks the moment it was actually ready.

Memory

With the libraries loaded the server sits at about 350 MB. Reading a book — the import, and Place NERs from the drawing — happens in a separate Python process that exits when the job ends, so the server does not grow with the books it has read. The browser is the other half: the Drawing viewer keeps one book open at a time and closes it when you change drawing, project or screen. If the machine is short of memory all the same (a laptop with many other things open), the import and the viewer are the first to slow down, well before anything fails; closing other programs helps more than restarting the server.

The watchdog: it comes back on its own

The second task autostart.bat creates, NER Analyzer watchdog, runs every two minutes, probes /api/auth/state twice (one timeout during a heavy export is not a dead server) and starts the server again if it does not answer — it never restarts one that is answering. Nor one that is starting (a process younger than three minutes), nor one that is merely slow (the port accepts the connection but no answer comes within 20 s): that one is restarted only after three consecutive checks, six minutes. One check runs at a time — the next waits for the previous one to finish. Before restarting it writes the machine's memory state, the five largest consumers and the standby and power events of the last half hour to data\watchdog.log, so the cause of a fall is recorded rather than reconstructed later. After the start it polls the health check for up to 150 s. data\watchdog-heartbeat.txt is a single line, rewritten on every check: that is how to know the watchdog is alive without waiting for a failure.

A laptop on battery

A task created by Windows is born with three defaults that kill a server silently: do not start on battery, stop when switching to battery and end after 72 hours. autostart.bat turns all three off on both tasks (tools\task-harden.ps1) and says, for each, [ok] … runs on battery, is not stopped on battery, has no time limit. If it says [*], the task still works on mains power, and the message names the boxes to untick in Task Scheduler (the Conditions and Settings tabs). On an installation older than this version, run autostart.bat once.

How to tell the watchdog is alive: open data\watchdog-heartbeat.txt. The time in it must be no more than two or three minutes old. A stale time means the watchdog stopped running — and that a fallen server will not come back by itself.

In the browser, while the server is out: the top bar shows the red pill server not answering — reconnecting, every action answers the server is not answering…, and the page polls /healthz every five seconds. When the server is back, the session and the project are reloaded by themselves and the notice says the server is back. A server that is down does not end the session; the sign-in screen appears only when the 12-hour session has actually expired.

tools\server-start.cmd starts the server through the scheduled task when it exists, and only without it as a process of its own. The difference matters: a process started by a session (a remote terminal, a tool) dies with it; started by the Task Scheduler it belongs to nobody's session.

Backup

Everything lives in data\ner.sqlite3 (plus the -wal and -shm files) and in data\uploads\. backup.bat writes a consistent copy of the database — valid even while the server is running, because it uses SQLite's backup API instead of copying the file — and the uploaded documents, into data\backup-YYYYMMDD-HHMMSS\ (or a backup-… folder inside the folder you name with backup.bat --to D:\folder). backup.bat --restore data\backup-… puts a backup back, with the server stopped; what was there is kept in data\replaced-YYYYMMDD-HHMMSS\, not deleted. A backup can be restored into another folder or on another computer with nothing to edit: when the server next starts, it points the record of every drawing and TEAP at this installation's own data\uploads. A backup before deleting a project or installing a new version costs seconds.

When something does not respond

  1. Wait two minutes — with the watchdog installed, it brings the server back by itself. If it does not, look at the time in data\watchdog-heartbeat.txt: stale, the watchdog is not running — start the server with tools\server-start.cmd and run autostart.bat again.
  2. Read the end of data\server.log. If the server is up and the page is blank or odd, press Ctrl+Shift+R — the browser is holding the old interface; the amber pill in the top bar says exactly when that is happening.
  3. stop.bat then start.bat; read data\watchdog.log to find out why it fell. A fall with no traceback and no ===== stopped ===== line in the log is a process killed from outside — memory, leaving standby or a policy of the machine; the watchdog log records the memory and the power events of the previous half hour. Close the browser and Outlook before exporting a whole book.
  4. Run .python\python.exe tools\check_env.py — it names any missing dependency instead of throwing a traceback mid-request.
  5. Port 8000 taken by another program: start.bat --port 8080. The watchdog always probes port 8000: a server on another port is not watched.

Installing on another machine

To move one project — not the application — to another computer, use Export and Import a project package on the Projects screen.

One .zip file, a few clicks at the other end, no administrator rights needed, and no internet connection. The full walkthrough — prerequisites, installation, first sign-in, updating, backup, uninstalling and common problems — is in the installation manual, docs\INSTALL.html, which ships with the package.

In short: on the source machine, build_package.bat writes dist\ner-analyzer-5.1.1-windows.zip with the application, the compiled screens, the manuals, the tests, every Python package and Python itself — and no data: no projects, no drawings, no accounts. On the target machine there is nothing to install first: unzip anywhere, right-click setup.bat → Run as administrator (a double-click asks Windows for the rights itself) — or, where administrator rights cannot be granted, double-click setup-noadmin.bat, which installs for that account only — and create the first account. setup.bat installs into %LOCALAPPDATA%\Programs\ner-analyzer for the person signed in, registers the sign-in task and the watchdog, starts the server, opens the browser, puts an NER Analyzer shortcut on the desktop and deletes the installation files, leaving only the application. An existing installation is backed up and replaced: its data is kept, and the old version is moved aside to ner-analyzer.previous. Opening install.bat in the package hands over to setup.bat.

On a Mac (Apple Silicon — M1 or later — macOS 11 or later) the package is ner-analyzer-5.1.1-macos-arm64.zip, built with python tools/make_package.py --platform mac. It carries its own Python 3.12 and the same pinned packages as the Windows one, and needs no administrator password: setup.command installs into ~/Applications/ner-analyzer, registers a launch agent for that account (the server starts at sign-in and again if it stops — what the watchdog does on Windows), starts the server, opens the browser, puts an NER Analyzer link on the Desktop and removes the installation files. An existing installation is backed up and replaced, its data kept. The mac folder of the installation holds start, stop, backup, run-tests, autostart and uninstall, each a .command. The steps, and what to do when macOS says it cannot verify the developer, are in the installation manual.
