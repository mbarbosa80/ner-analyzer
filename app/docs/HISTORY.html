How we worked

The application was written by Claude (Anthropic) from the specifications, the real documents and the screen-by-screen reviews of Marcelo Barbosa — the way a text editor is used to write code: the AI took part in writing the application, and is no part of what runs. Nothing inside the application calls out to any model, service or account.

  • The specification came in two master prompts: the first (26 Aug) described the full coverage study — reading the VDB and the TEAP, scale, matching, the 90/70 m rules, coverage, reports — and the second, the same day, “V2”: the register of canonical NERs.
  • The reviews came from Marcelo in three forms: a 14-minute voice note walking the application screen by screen (the 2 Sep simplification), a written list of Melhorias Propostas (the 3 Sep pass) and annotated screenshots (the 10 Sep pass). Every ambiguity went back as a question before it became code.
  • The real documents — the HND book (34 pages, 38 MB), the TEAP v2.0 (15 sheets, 17,496 rows, 96 venues) and later the OWC, RIV, ALA, SPC, OSP and FRG books — were the yardstick for everything. Several decisions below were made by measuring against them, not by assuming.
  • The delivery cycle: code written and tested in a development environment, packaged, installed on Marcelo's machine, the test suite run on his Python, the server restarted and the manual updated — his rule since 27 Aug: “the manual ships with every change”. Before every large pass, a backup of the database and the code.

11/09/2026 Version 2.1.0 — Python comes in the package. The 2.0.0 package had a hole: it promised “no internet, nothing outside the folder” yet required Python 3.12 to be downloaded and installed first — it worked on the first machine only because that one already had it. Marcelo's question (“did you build an installer that installs Python when the machine has none?”) exposed it. Three ways out were put on the table: embed the official python.org embeddable package (11 MB, nothing outside the folder); carry the python.org installer inside the zip and run it silently (installs Python on the machine, touches PATH, may be blocked by corporate policy); or freeze everything into a single .exe (PyInstaller: a large, fragile build with PyMuPDF, numpy, pandas and OR-Tools, corporate antivirus distrusts it, a rebuild per release). Marcelo chose the first and asked that the third stay on record, to be reconsidered when the application is commercialised. Done: install.bat unpacks Python 3.12.10 into .python\, writes its search path (python312._pth), checks the Python Software Foundation signature, installs pip from the bundled wheel and the lock file's packages, and places msvcp140.dll beside Python only when Windows lacks it (the copy numpy ships). Every script now looks for .python\ before .venv\; run.py hands backend\ to uvicorn explicitly because the embedded Python ignores PYTHONPATH by design. The package builder fetches the python.org zip once and refuses any copy that does not match the pinned SHA-256. A scan of the 47 wheels showed who needs the Visual C++ runtime: numpy, pandas and shapely carry their own copy; PyMuPDF, OR-Tools and RapidFuzz expect the system's. Tested on a clean install with Python removed from PATH. Package: 97 MB.

18/09/2026 Version 2.4.0 — the installer that erases itself. Marcelo's request: “an installer that also installs Python, as we did last time, but this time the installer must destroy every installation file. 18/09/2026 Version 2.4.2 — the installer finishes erasing itself. In the clean-install test of 2.4.0, setup.bat deleted every file of the unzipped package but left the empty folder behind. The reason is a Windows rule: a folder cannot be removed while any process still has it as its working directory — and setup.bat's own window is not the only candidate. Called from inside another script, setup.bat hands the directory back to its caller the moment it exits; an Explorer window open in the folder holds it just the same. The clean-up now keeps trying for about 45 seconds. The files always went on the first pass; it is the empty folder that has to wait. The same day it turned out the 2.4.1 package's INSTALL.txt still said 2.4.0 — a test now holds it to the VERSION file, as it already did for the manuals.
18/09/2026 Version 2.4.3 — the clean-up only scratched the surface. The clean-install test of 2.4.2 showed what 2.4.0 had hidden: of the 142 files in the unzipped package, the clean-up deleted 22 — exactly the ones at the root — and left the 120 that sit inside folders. MANIFEST.txt writes its paths with forward slashes (backend/app/config.py), as any manifest that crosses systems does, and Windows' del refuses a forward slash: it reads it as the start of an option. The clean-up script now converts each path before deleting. The lesson stays: the first version “worked” on screen — not one error message, because every line ends in 2^>nul — and only a test that went and looked at the folder afterwards saw it was still there.
18/09/2026 Version 2.4.4 — what the installer test found inside the application. With 2.4.3 installed into a clean folder, running run-tests.bat from there reported nine failures. Eight were expected and were not failures: the setup.bat tests have no subject in an installation setup.bat made, because it does not copy itself into one — they now skip there, as the bundled-package tests already did. The ninth was real, and it was in the application: the audit log was ordered by time alone. A bulk decision stamps every row it writes with a single instant, and Windows' clock ticks coarsely enough that the click before it can land on the same one; tied, SQLite returns those rows in whatever order it likes. The screen whose whole purpose is to say who decided what, and in which order could show an order that never happened. The tie-break is now the row number. It had never shown on Linux, where the clock is too fine to tie.

Decisions that shaped the application

  • Colour does not classify. On the real book every equipment-room label is the same red; criticality is in the text. The app reads the text and reports a confidence; the blue/red/yellow convention is how it draws its own output.
  • Code before name. The drawings carry the TEAP's code taxonomy; matching on the code is exact and explainable. The name is the fallback, and a similar name is never confirmed on its own.
  • Rule A is authoritative, and reconciled. Network Ports = quantity × ports per unit on 17,495 of 17,495 checkable TEAP lines; the importer re-verifies at every import and warns per line.
  • A straight line is never presented as compliant without qualification. Every distance with no traced route carries the warning and the slack factor; the 90 m is a permanent link, not a straight line.
  • A room and an occurrence are different things. A room drawn on four sheets is one NER with four markers. The identifier never changes; renaming writes history.
  • Merge on proof, ask on suspicion, never assume. An identical label is necessary and not sufficient; level and building agreeing is what merges by itself; an unknown level is a question.
  • The TEAP rules (2.2.0). It says whether an area is served: the check runs from the TEAP to the drawing and never back, a space with no ports requested is nobody's work, and a newer TEAP replaces the older one. The exception — wired connections the TEAP requests without counting a port — stays in sight, with no invented port: what a connection is worth is for whoever owns the TEAP to decide.
  • The same space on several sheets follows the NER rule (2.2.0): merge on proof (same code, same level read off the title block), ask on suspicion, another floor is never inferred — and the question is asked only where the answer changes the result.
  • The drawn wireless is the space's wireless (2.5.0). The TEAP's wireless line counts until the access points are drawn; from then on the points carry the port and the TEAP line leaves the sum — never both. With nothing drawn, the TEAP rules.
  • A figure on screen is a filter, and a decision is reversible (2.6.0). The tiles are counted from the rows the table shows, so they never disagree with it; “confirmed by you” counts people, not the matcher; and undo returns the matcher's answer, never a blank.
  • A symbol is read by its shape, against a reference the real document gave (2.15.0). The NER block's word is strokes, not text; the app keeps the strokes of one real block as a template and matches by geometry — centred, turned, scaled, Chamfer distance — never by colour, never by OCR. Another venue's block, another word, is not read until its block joins the reference.
  • Only a NER serves. TER, IDF, COW and DIVA node are drawing and nothing else; the refusal is the server's.
  • There is one proposal, and it is the drawing. The app says what each placement costs; the engineering decision stays with a person, room by room.
  • The decision lives where the data lives. The chosen room sits on the TEAP line; the criticality, on the NER; re-running any step never erases a decision.
  • When a column goes, the warning it carried is moved, not lost. Method and confidence → the Matching sheet; demand rule → Needs validation; audit log → Account & security.
  • The data statement says what the application does, and what it does not protect. It claims compliance with no policy; it lists “no encryption at rest”. A notice that only reassures manufactures confidence that is not there.
  • Local, on 127.0.0.1. The strongest protection is the loopback address, not the password; removing it is another deployment, with other obligations.
  • The package carries no data. The builder refuses a package with the data folder; carrying data is a separate, deliberate act.
  • Visual changes are decided by looking at a real PDF, not by reading the code — the black ring, the darker name, the tag under the dot.
  • The manual ships with every change, with the control labels never translated. Bilingual (Portuguese and English) up to 2.13.0; English only from 2.13.1, to keep it fast to update.
  • The package carries its own Python (2.1.0). A prerequisite that needs the internet and an installer contradicts a package that promises neither; the python.org embedded Python closes that without putting anything outside the folder.
  • Deliberately open: the single .exe. Freezing the application into an executable (PyInstaller or similar) was set aside in 2.1.0 for its cost and fragility, but Marcelo intends to commercialise the application and asked for the option to be raised again when that moves forward — a product that is sold may justify a signed installer and an executable of its own.
